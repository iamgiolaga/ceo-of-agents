# Migration 0.12.0 to 0.13.0

Version 0.13.0 makes one change, in the plugin only:

- **A removed department's folder goes to the archive.** When the CEO removes a department, the `departments` skill now moves its folder, `departments/<id>/`, to `archive/departments/<id>/` instead of deleting it, marks its documents `status: archived`, and points links in current files to the new path, with the archiving steps of `schemas/document.md`. The removal decision covers the move, so no separate approval is asked. The agent file, the item in `org.yaml` and the routing row are still removed. The folder is deleted only if the CEO asks for that explicitly, and that stays a delete action that needs the CEO's OK.

No schema changes: `org.yaml` stays `org/5` and `company/state.md` stays `state/1`. No hq file changes apart from the version: the steps live in the plugin's `departments` skill and `schemas/document.md`, and the hq's `CLAUDE.md` already says that archived documents keep their path under `archive/`. A department removed before this version stays as it is: its folder is in the git history.

## Edits

`org.yaml`: `framework_version: 0.12.0` becomes `framework_version: 0.13.0`.

`company/state.md`: frontmatter `framework_version: 0.12.0` becomes `framework_version: 0.13.0`.

In the summary to the CEO, add one plain line: from now on, removing a department moves its notes and analyses to the archive instead of deleting them; they are deleted only if the CEO asks.
