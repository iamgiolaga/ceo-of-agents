# Migration 0.2.0 to 0.3.0

Version 0.3.0 changes the command surface. The setup wizard is renamed from `init-org` to `init-fleet`, and it is the only command the CEO types. The four CoS procedures (`intake`, `record-decision`, `weekly-brief`, `portfolio-brief`) stay in the plugin but are hidden from the `/` menu (`user-invocable: false`): the CoS invokes them from plain-language requests, and typing `/ceo-of-agents:intake` and the like no longer runs them. Custom departments also get the purpose-aware account-separation line that catalog departments already have.

No schema changes: `org.yaml` stays `org/2` and `company/state.md` stays `state/1`.

An hq that is not migrated keeps working: the CoS can still invoke the procedures. What changes for it is only that the CEO can no longer type them, and that its `CLAUDE.md` still names them as slash commands.

## Edits

`org.yaml`: `framework_version: 0.2.0` becomes `framework_version: 0.3.0`.

`company/state.md`: frontmatter `framework_version: 0.2.0` becomes `framework_version: 0.3.0`.

`CLAUDE.md`, table "What the CEO says and what you do": each procedure is named as a skill, not a slash command. Keep the rest of each row.

```
# before
| ... | Run `/ceo-of-agents:intake`: restate it, ...
| ... | Run `/ceo-of-agents:record-decision`: write the record, ...
| "Brief" / "briefing" / weekly update | Run `/ceo-of-agents:weekly-brief`. |
| "Portfolio" / "what waits on me across orgs" | Run `/ceo-of-agents:portfolio-brief`. |

# after
| ... | Use the `intake` skill: restate it, ...
| ... | Use the `record-decision` skill: write the record, ...
| "Brief" / "briefing" / weekly update | Use the `weekly-brief` skill. |
| "Portfolio" / "what waits on me across orgs" | Use the `portfolio-brief` skill. |
```

The `portfolio-brief` row exists only in a holding.

`CLAUDE.md`, holding only, section "Holding role": `` `/ceo-of-agents:portfolio-brief` reads`` becomes `` The `portfolio-brief` skill reads``, and `` If one is listed, `/ceo-of-agents:portfolio-brief` skips`` becomes `` If one is listed, the `portfolio-brief` skill skips``.

`CLAUDE.md`, section "Skills available": replace the body of the section with the following (drop the `portfolio-brief` line in a company hq).

```
These are your own procedures. You invoke them when a request calls for one (see "What the CEO says and what you do"). They are hidden from the CEO's `/` menu: the CEO never types them and just talks to you in plain language.

- `intake`: frame a new idea or request and route it.
- `record-decision`: turn an answered card into a decision record.
- `weekly-brief`: write the dated brief and summarize it.
- `portfolio-brief`: compose the cross-org brief and pending list.

The `ceo-of-agents` plugin must be enabled in this repo for these skills to be available. Claude Code on the web does not load plugins: there, tell the CEO these procedures are unavailable and suggest a local session for work that needs them.
```

`operating-model.md`:

- "Rhythms", row "Weekly brief": `` the CoS runs `/ceo-of-agents:weekly-brief` and writes`` becomes `` the CoS runs its `weekly-brief` procedure and writes``.
- "Working surfaces": replace the first sentence ("Anything that opens this folder with the plugin enabled works: ...") with:

  ```
  Full support: Claude Code on your own machine with the plugin enabled (terminal, the desktop app's Code tab, VS Code, JetBrains through its terminal). Claude Code on the web loads this hq's `CLAUDE.md` and `.claude/agents/` but not the plugin, so the CoS procedures are unavailable there.
  ```

  The 0.2.0 text listed a web code session as fully working, which was wrong.
- "Plugin requirement": replace the body with "The `ceo-of-agents` plugin must be enabled in this hq. The CoS procedures (`intake`, `record-decision`, `weekly-brief`) come from it. They are hidden from the `/` menu: the CEO never types them, the CoS invokes them." A holding adds the line "The holding also uses the `portfolio-brief` procedure."
- "How to start" (optional, cosmetic): see `templates/instance/operating-model.md` in the plugin for the 0.3.0 wording with plain-language examples.

Custom departments: for each department in `org.yaml` with `from_catalog: custom`, append this section at the end of `.claude/agents/<id>.md`.

```
## Account separation
Use only this org's accounts and the connectors in your tools list. Never use another org's credentials, and never use other accounts (<example>).
```

`<example>` is `for example an employer's` when `org.purpose` is not `job`, and `for example the CEO's personal accounts; the employer's accounts used for this job are this org's accounts` when it is `job`. Catalog departments do not change.

The CoS shows the custom department edits in the diff like any other. Writing into `.claude/agents/` may need the CEO to approve a permission prompt.
