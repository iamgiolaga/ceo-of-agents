# Migration 0.7.0 to 0.8.0

Version 0.8.0 makes one change:

- No more connector question at the first session. Until now, when `accounts.local.yaml` was missing (the first session of an hq, a new computer or a fresh clone), the chief of staff listed the connectors (MCP servers) visible in the session, asked the CEO which belong to another account, wrote them as `forbidden_connectors` to `accounts.local.yaml` and mirrored them as deny rules in `.claude/settings.local.json`. Users found the question technical and its "this machine" scope confusing. The step is removed: the CoS no longer asks it and no longer writes either list.

What stays:

- The written account-separation rule in `CLAUDE.md`: never use another account's connectors for this org, and never hand them to agents.
- Every department starts with no connectors and gets one only through a decision card.
- `accounts.forbidden_connectors` in `org.yaml` stays an optional list, filled through a decision card.
- `accounts.local.yaml` stays untracked and keeps only `repo_paths` (local clone paths, which really differ per computer). The "Repos on this machine" step still asks for them.

No schema changes: `org.yaml` stays `org/4`, `company/state.md` stays `state/1`.

Local files are not touched. Existing `checked` and `forbidden_connectors` keys in `accounts.local.yaml` and existing rules in `permissions.deny` of `.claude/settings.local.json` stay as they are: they are now the user's own local choice, and Claude Code keeps enforcing the deny rules. The CoS no longer reads, adds to or asks about them. Neither file is part of the migration commit.

An hq that is not migrated keeps working: its `CLAUDE.md` still holds the old step, so the CoS keeps asking the question when `accounts.local.yaml` is missing.
