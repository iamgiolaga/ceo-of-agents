# Migration 0.8.1 to 0.9.0

Version 0.9.0 changes the setup wizard and the generated hq:

- The chat language is asked first (or inferred from text typed with the command). The file language stays in question 4.
- Free-text answers can be multi-line lists and are kept verbatim.
- A custom department is asked whether it needs to run commands. Yes adds `Bash` to its tools.
- A new question asks how commits and pull requests are signed. The answer is written to `attribution` in the hq's `.claude/settings.json`: absent means the Claude Code default, custom text, or empty strings for none.
- A product repo (or the issues home) can be recorded as not yet existing, `planned: true`. The setup seeds an action item asking the CEO to create it (`gh repo create`).
- Any optional question can be answered "later": it becomes an action item in the pending list.
- Per-department option "top model, workers included": `workers: same` on a department in `org.yaml`, only together with a `model` equal to the first entry of `models.tiers`. Its workers run on the same tier, never more capable than the parent.
- The wizard's final checks no longer flag `Agent(...)` as a leftover ellipsis, and fall back to Ruby's YAML when PyYAML is missing.
- The wizard states that it writes files itself, even if a user-level instruction says to delegate.
- A holding's chief of staff shows the aggregated pending list of its registered companies at session start (the new "Portfolio pending list" bullet). The full analysis stays in the `portfolio-brief` skill.

What touches an existing hq: only `CLAUDE.md`, and the versions in `org.yaml` and `company/state.md`. The wizard questions, the catalog and the department template are in the plugin only. Their rendered text is unchanged for existing departments.

No schema changes: `org.yaml` stays `org/4` (two new optional keys, `workers` per department and `planned` per repo; existing files need none), `company/state.md` stays `state/1`.

`.claude/settings.json` is not edited by the migration: without an `attribution` key, Claude Code's default applies. Agent files are not edited: their worker lines stay correct while no department uses `workers: same`.
