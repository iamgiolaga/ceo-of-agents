# Migration 0.4.0 to 0.5.0

Version 0.5.0 changes the generated hq in three ways:

- Vision and strategy. `company/vision.md` (what the org does, for whom and why; stable) and `company/strategy.md` (stage and current focus; kept up to date by the CoS from decisions). The CoS reads both at session start and challenges requests against them.
- Forbidden connectors per machine. The same connector name can mean a different account on another machine (a claude.ai connector follows the claude.ai account signed in there), so a list synced through git can be wrong elsewhere. `accounts.forbidden_connectors` in `org.yaml` now holds only names that mean the same account on every machine. The rest go in `accounts.local.yaml`, which git does not track. The CoS fills it with the CEO on each new machine or fresh clone and mirrors it as deny rules in `.claude/settings.local.json`, so Claude Code blocks those connectors for every agent.
- The CoS says so when a pull fails and continues with the local copy. The plugin's `intake`, `record-decision` and `weekly-brief` skills now check `git remote` before pulling; that part needs no hq edit.

The wizard's gates and connectors questions are rewritten in plain language; that changes no hq file.

No schema changes: `org.yaml` stays `org/2` and `company/state.md` stays `state/1`.

An hq that is not migrated keeps working: the skills read the new files only if present. What it misses is the vision anchor and the per-machine connector check.

## Edits

`org.yaml`: `framework_version: 0.4.0` becomes `framework_version: 0.5.0`.

`company/state.md`: frontmatter `framework_version: 0.4.0` becomes `framework_version: 0.5.0`.

New `company/vision.md` and `company/strategy.md`, rendered from `templates/instance/company/` in the plugin. The CoS asks the CEO the three questions of the wizard's question 3 for this org's purpose and level, or drafts the answers from `company/state.md` and the decision records and asks the CEO to confirm them. `{{STAGE}}` is one of the stages listed there; `{{DATE}}` is today. Nothing is invented: an answer the CEO does not give stays "not decided yet".

New `.gitignore` at the hq root (or append to the existing one):

```
# Per-machine files: the same connector name can mean a different account on another machine.
accounts.local.yaml
.claude/settings.local.json
```

`accounts.forbidden_connectors` in `org.yaml`: the CoS reviews each entry with the CEO. An entry whose name can mean a different account on another machine (for example any `mcp__claude_ai_*` pattern) moves out of `org.yaml` into `accounts.local.yaml` on the machines where it applies. Entries that mean the same account everywhere stay. If the CEO is unsure, move the entry, as the wizard does: the CoS asks again on every machine where `accounts.local.yaml` is missing, so no machine goes unchecked.
