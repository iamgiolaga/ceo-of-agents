# Migration 0.9.0 to 0.10.0

Version 0.10.0 adds a fifth fleet purpose, `personal`: an hq that looks after the CEO's own personal life.

- The setup wizard offers `personal` (company level, not asked). Its two questions are "What part of your life should this fleet look after?" and "What would make it worth it?", its stages are `setting up` and `running`, and `company/vision.md` gets the headings "What this is for", "What matters to me" and "Principles".
- Three new advisory catalog entries, offered only for `personal`: `health`, `money` and `paperwork`. Like legal, finance and tax they have no `Agent` and no `Bash`, get only read-only connectors, and never file, sign or pay. The company legal, finance and tax entries are not suggested for `personal`. Custom departments stay available, with the usual commands question.
- Personal data lives only in `private/`, a folder of the hq that the generated `.gitignore` excludes. It does not travel between computers: the chief of staff says so at session start when it is empty. Tracked files hold structure, decisions and pointers only.
- A personal hq gets no questions about product repos or a roadmap board (`repos: []`, `tracker: none`), no holding policy and no employer rules (`policy: null`, `employer_rules: null`), and is never registered in a holding portfolio: `portfolio-brief` and the holding's session start skip it like a job hq.

What touches an existing hq: nothing for a company hq apart from the version (and one comment in `org.yaml`), because no existing hq has purpose `personal` and every other purpose renders the templates exactly as in 0.9.0. A holding hq also gets two one-line edits in `CLAUDE.md`, so that its session start and its holding rules skip a personal hq as they already skip a job hq.

No schema changes: `org.yaml` stays `org/4` (`personal` is a new allowed value of `org.purpose`, and `health`, `money`, `paperwork` new allowed values of `from_catalog`; existing files need none), `company/state.md` stays `state/1`. No agent file, charter or `.claude/settings.json` changes.

## Edits

`org.yaml`: `framework_version: 0.9.0` becomes `framework_version: 0.10.0`. If the `purpose:` line ends with the comment `# job | product | startup | company`, append ` | personal` to it.

`company/state.md`: frontmatter `framework_version: 0.9.0` becomes `framework_version: 0.10.0`.

`CLAUDE.md`, holding only (`org.level: holding`; a company hq skips this part):

1. Section "Session start (always)", the **Portfolio pending list.** bullet. Replace:

   ```
   and read only `org.purpose`: if it is `job`, skip the org (a job hq never belongs in a portfolio; say so once).
   ```

   with:

   ```
   and read only `org.purpose`: if it is `job` or `personal`, skip the org (a job or personal hq never belongs in a portfolio; say so once).
   ```

2. Section "Holding role". Replace:

   ```
   - An hq whose `org.purpose` is `job` is never registered in `portfolio.yaml`.
   ```

   with:

   ```
   - An hq whose `org.purpose` is `job` or `personal` is never registered in `portfolio.yaml`.
   ```

## Check after applying

- `framework_version: 0.10.0` in `org.yaml` and in `company/state.md`.
- Company hq: `git status --short` shows only `org.yaml` and `company/state.md`.
- Holding hq: `git status --short` shows only `org.yaml`, `company/state.md` and `CLAUDE.md`; `grep -c 'is `job` or `personal`' CLAUDE.md` returns 2.
