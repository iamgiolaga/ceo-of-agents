# Migration 0.3.0 to 0.4.0

Version 0.4.0 adds three working rules to the generated hq:

- Elevated grants need a reason. Adding a department, or a tool or connector to an existing one, goes through a decision card with a one-line reason for each connector, `Edit`, `Write`, `Bash` or `Agent` grant. A reply to a denied permission is not a grant.
- Task splitting. The CoS keeps one ask as one task unless a part has a different owner, needs different permissions, can run in parallel, waits on another part, or is an independent review.
- Blocked and failure hygiene. Workers and departments name what is missing and who must act, do not repeat an unchanged blocked report, check that writes landed, and stop after two failed retries.

No schema changes: `org.yaml` stays `org/2` and `company/state.md` stays `state/1`.

An hq that is not migrated keeps working. The plugin's `intake` skill already carries the splitting rule; what an unmigrated hq misses is the rest, in its own `CLAUDE.md` and agent files.

## Edits

`org.yaml`: `framework_version: 0.3.0` becomes `framework_version: 0.4.0`.

`company/state.md`: frontmatter `framework_version: 0.3.0` becomes `framework_version: 0.4.0`.

`CLAUDE.md`, section "Departments": add this paragraph at the end of the section, just before "## Orchestration".

```
Adding a department, or giving an existing one a new tool or connector, goes through a decision card. Before writing the card, re-read the draft (scope, tools, connectors, model) and give a one-line reason for each elevated grant: any connector, `Edit`, `Write`, `Bash` or `Agent`. Drop a grant that has no reason. A reply from the CEO to a denied permission is not a grant by itself: do not widen an allowlist on the strength of it; the grant goes through the card.
```

`CLAUDE.md`, section "Orchestration": add this bullet right after the bullet that starts with "Hands-on work (bulk reading, long drafting, code, commands) goes to others".

```
- Splitting work: one ask is one task by default. Split it only where a part has a different owner, needs different permissions, can really run in parallel, must wait for another part to finish, or is an independent review. Write each dependency into the briefs. A split never adds an approval and never skips one. A review brief stands on its own, without the author's context, and names who receives the verdict.
```

`.claude/agents/worker.md`: replace the bullet "If the brief is unclear or blocked, stop and say what is missing." with these three bullets.

```
- If the brief is unclear or you are blocked, stop and say what is missing: the capability (tool, access or input) and who must provide it. Do not send the same blocked report again while nothing has changed.
- After every write, check that it landed (read the file back, check the command output). An empty or unchanged result is a failure, not a success.
- After two failed retries of the same step, stop and report what you tried and what failed.
```

`.claude/agents/reader.md`: add this bullet at the end.

```
- If a source cannot be read, name what is missing (access, file, tool) and who could provide it. A page or file that comes back empty when it should hold content is a failed read, not an answer. Retry a failed read at most twice, then report it as failed.
```

Every department agent file (`.claude/agents/<id>.md`, catalog and custom): in section "Method", add this step after the last numbered step, numbered one higher (step 5 for catalog departments, step 4 for custom ones, unless the org edited the list).

```
<n>. When blocked, name the missing capability (tool, access or input) and who must act, and do not repeat the same blocked report while nothing has changed. Check that every write landed: an empty or unchanged result is a failure. Stop after two failed retries and report.
```

Existing grants are not re-reviewed by this migration. The CoS may list any connector without a recorded reason in its status and propose a card to keep or drop it.

The CoS shows the agent file edits in the diff like any other. Writing into `.claude/agents/` may need the CEO to approve a permission prompt.
