# Migration 0.6.0 to 0.7.0

Version 0.7.0 makes three changes:

- Agents are named after their personas. A department now has two names. Its id (for example `engineering`) stays the key for `departments/<id>/charter.md`, decision cards and handoffs. Its agent name is the new `agent` field in `org.yaml`: the persona in lowercase (for example `mike`), or the id when the department keeps its role name. The agent file is `.claude/agents/<agent>.md`, the chief of staff routes and dispatches by agent name, and the CEO opens a department directly with `claude --agent <agent>`.
- A version check at session start. A new hidden skill, `hq-version`, compares the hq's `framework_version` with the installed plugin version, lists the migrations still to apply and adds one A item asking the CEO's OK. It applies them, one step at a time, only after that OK.
- Two approval rules for the chief of staff: ask for one gated action per question, named precisely, and act right after a clear yes; when the harness blocks an approved action, try it first, then report the block plainly with the exact command the CEO can run, and never work around it. Department agents get the second rule in one line.

Schema change: `org.yaml` goes from `org/3` to `org/4` (one new required key per department, `agent`). `company/state.md` stays `state/1`.

An hq that is not migrated keeps working: the skills read a department without `agent` (an `org/3` file or older) as `agent` equal to its `id`. The hq's own `CLAUDE.md` has no version check yet, so the check reaches it through `intake`, which runs the `hq-version` skill once. What an unmigrated hq misses is persona agent names and the check at session start.

## Edits

`org.yaml`:

- `schema: org/3` becomes `schema: org/4`.
- `framework_version: 0.6.0` becomes `framework_version: 0.7.0`.
- In every department item, add `agent: <agent>` right after its `id:` line. Derive `<agent>` with the same rules as the setup wizard (question 6 of the plugin's `init-fleet` skill):
  - If the department's `display_name` equals its role name (ignoring case), `<agent>` is the department id. The role name is in the Role column of the routing table in `CLAUDE.md`, or in the intro line of the department's agent file ("the <role> department of").
  - Otherwise `<agent>` is the persona slug: remove accents, lowercase, keep letters and digits, turn every other run of characters into one hyphen, drop a leading or trailing hyphen ("Mike" gives `mike`, "Anna Maria" gives `anna-maria`, "Zoë" gives `zoe`). It must match `^[a-z][a-z0-9-]*$`. If nothing usable is left, ask the CEO for a short name in Latin letters.
  - Clashes: an agent name must differ from every other department's agent name and id, and from `reader` and `worker`. For each clash, ask the CEO one plain question with nothing preselected, for example: "Your engineering and support departments would both be called `mike`. Pick another name for one of them, or I call one of them `mike-support`: which one?" The second option is always `<agent>-<department id>` for the department the CEO names. Check again after each answer.
- If the item-shape comment above `departments:` is present, replace its first two lines with:

  ```yaml
  #  - id: engineering            # kebab-case; departments/<id>/charter.md, cards and handoffs
  #    agent: mike                # agent name: persona in lowercase, or the id; file .claude/agents/<agent>.md
  ```

  The old first line reads `#  - id: engineering            # kebab-case; files .claude/agents/<id>.md, departments/<id>/charter.md`.

`company/state.md`: frontmatter `framework_version: 0.6.0` becomes `framework_version: 0.7.0`.

## Check after applying

- `schema: org/4` and `framework_version: 0.7.0` in `org.yaml`; `framework_version: 0.7.0` in `company/state.md`.
- Every department in `org.yaml` has `agent`. Agent names are unique, match `^[a-z][a-z0-9-]*$`, and none equals another department's id, `reader` or `worker`.
- For each department, `.claude/agents/<agent>.md` exists and its `name:` equals `<agent>`. No `.claude/agents/<id>.md` is left for a department whose agent differs from its id.
- With departments: `grep -n "Route by agent name" CLAUDE.md` finds one line.
- `grep -n "Plugin version" CLAUDE.md` finds one line.
- `grep -n "Ask for an OK one gated action at a time" CLAUDE.md` and `grep -n "If the harness blocks an approved action" CLAUDE.md` each find one line.
- Every `Agent(...)` entry in `.claude/agents/*.md` and in `.claude/settings.json` names an existing `.claude/agents/<name>.md`.
