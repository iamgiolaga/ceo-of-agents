# Operating model: {{ORG_NAME}}

How the CEO works with this org. Generated by ceo-of-agents {{FRAMEWORK_VERSION}} on {{DATE}}.

## One entry point

The CEO talks to the chief of staff (CoS). The CoS frames, routes, records everything in hq and brings back only what needs the CEO. hq (this repo) is the single source of truth: if it matters, it is written here.

## Roles

| Role | What it does |
|---|---|
| CEO (`{{CEO_ROLE_ID}}`) | Sets direction, answers decision cards, gives the OKs the gates require. |
| CoS ({{COS_DISPLAY_NAME}}) | Single point of contact. Frames, routes, records, challenges. Owns hq. Does no deep execution. |
| Departments | Vertical specialists with a charter, a tool allowlist and a model tier. See `org.yaml` and `departments/`. |
| Workers | Cheaper agents for bulk reading and hands-on work: `reader` (read-only) and `worker` (hands-on), defined in `.claude/agents/`. One model tier below their parent. |

## Talking to departments

The CEO may talk to anyone; everything that matters comes back to hq and the CoS records it.

- **A. Through the CoS.** The CoS briefs the department, checks the result and summarizes.
- **B. Direct message inside the CoS session.** "Pass to <department>: [text]" The CoS forwards verbatim, returns the full answer verbatim, and may add a comment.
- **C. Direct session.** Run `claude --agent <agent>` from the hq folder, where `<agent>` is the department's agent name from the routing table in `CLAUDE.md`: its persona in lowercase (for example `claude --agent mike`), or its id when it has no persona. Inside a session you can also type `@` and pick the agent by that name. The department works on its own model and leaves a handoff in `inbox/` at the end. Decisions taken there become official only when the CoS records them. Strategic or cross-department reasoning goes through the CoS. Agents are defined inside hq, so `--agent` works only from inside this folder.

## Rhythms (on demand only)

No scheduled automation, no hooks. Nothing runs unless the CEO opens a session.

| Rhythm | What | How |
|---|---|---|
| Weekly brief | What changed, numbers, decisions needed | The CEO asks for a brief; the CoS runs its `weekly-brief` procedure and writes `company/briefs/YYYY-MM-DD-weekly.md`. |
| Batched approvals | Several OKs in one pass | Departments prepare, the CoS lists the codes in "Waiting on the CEO", the CEO approves by code. |
| Review | Risks, metrics trend, charters | On request. |

## How decisions flow

1. A question needing the CEO becomes a **decision card** in `company/decision-queue.md` with its own code `{{ORG_ID}}-D<n>`: context, options, recommendation, and exactly one of `proposed_by: <dept-id|cos>` or `needs analysis by: <dept-id>`.
2. The card is listed in "Waiting on the CEO" in `company/state.md`.
3. The CEO answers (in chat, by code).
4. The CoS runs `record-decision`: a numbered, immutable record in `decisions/`, an index row, the card removed, state updated.

To change a decision, a new record supersedes the old one; only the old record's status line changes.

## How approvals work

Gates live in `org.yaml` and are summarized in `CLAUDE.md`. Three tiers: free (do it, mention it), notice (one line before acting), ok (the CEO's explicit OK). The CoS does not ask for OKs the table does not require, batches asks into the pending list, and runs exactly the approved action. The CEO approves by code, for example `{{ORG_ID}}-A2`.

## The pending list and codes

"Waiting on the CEO" in `company/state.md` is the one list. Actions are `{{ORG_ID}}-A<n>`, decisions are `{{ORG_ID}}-D<n>`. Numbers grow monotonically and are never reused.

## Handoffs

A department leaves one file per handoff in `inbox/` (format in `inbox/README.md`). The CoS processes it at the next session start and deletes it in the same commit.

## Working surfaces

Full support: Claude Code on your own machine with the plugin enabled (terminal, the desktop app's Code tab, VS Code, JetBrains through its terminal). Claude Code on the web loads this hq's `CLAUDE.md` and `.claude/agents/` but not the plugin, so the CoS procedures are unavailable there. Chat-only surfaces without repo write access are read-only; their output comes back as files in `inbox/`.

## Plugin requirement

The `ceo-of-agents` plugin must be enabled in this hq. The CoS procedures (`session-start`, `intake`, `record-decision`, `weekly-brief`, `hq-version`, `departments`, `product-repos`) come from it. They are hidden from the `/` menu: the CEO never types them, the CoS invokes them.

Open a Claude Code session in the hq folder and say what you need in plain language. The CoS opens with a short status and the pending list. For example: describe an idea, say "decide X", "brief" or "approve {{ORG_ID}}-A1".
